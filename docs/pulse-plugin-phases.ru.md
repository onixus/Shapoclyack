# Фазы плагинов Pulse

Рабочий бриф для новых Rhai-проверок сканера. Контракт загрузчика, квитанция и
верификация остаются в [Pulse plugins](pulse-plugins.md). Этот файл говорит,
что ещё писать и в каком виде. Его можно дополнять: новая проверка дописывается
в открытую фазу или в новую фазу внизу, уже закрытые пункты не переписываются.

Снимок на 2026-11-09. После закрытия фаз 1–4 и 7 в
`scanner/pipeline/pulse_data/plugins/` лежит 50 плагинов. Это содержимое git:
образы его не копируют, на сенсор его ставит `scripts/fetch-pulse-plugins.sh`.
Имена сервисов ниже
сняты с `scanner/pipeline/pulse_data/probes.json`:
плагин видит поле `service` пробы, а не торговое имя продукта.
Фаза 6 разобрана: строки либо перенесены в фазу 7, либо закрыты как `blocked`.

## Как дополнять

1. Новый пункт кладётся в ближайшую открытую фазу, если у него уже есть имя
   сервиса и один запрос. Иначе — в фазу «заготовки» или в новую фазу.
2. У пункта есть статус. Меняется только статус и пустые поля «дописать».
   Готовый пункт не редактировать задним числом: уточнение — новая строка в
   журнале и, если смысл проверки другой, новый пункт.
3. Статусы: `todo` (можно писать), `doing`, `done`, `blocked` (с причиной),
   `dropped` (с причиной, пункт не удалять).
4. Фаза закрывается, когда у каждого её пункта статус `done`, `blocked` или
   `dropped`. Закрытую фазу не открывать заново: следующая работа — новая фаза.
5. Не копировать тела скриптов GenDec. Оттуда взяты только названия дыр.
   Скрипт, который ставит находку на открытый порт, сюда не переносится.

Шаблон нового пункта:

```text
### shapo_<имя> — <статус>
- Сервис: точное значение `service`, как его пишет проба.
- Порт без имени: только `unnamed && port == N`. Общий порт двум продуктам не отдавать.
- Запрос: один обмен. Что отправить и какой ответ разобрать.
- Находка: какое разобранное условие и какая серьёзность.
- Чисто: `return` без карты. Когда ответа достаточно, чтобы сказать «этого нет».
- Ошибка: `throw`. Обрезанный, чужой или непонятый ответ не бывает «чисто».
- Evidence: факт разбора, без тела, списка, секрета и дампа.
- Не делать: соседние команды, которые этот пункт не покрывает.
- Тест: какие три ответа заглушки обязательны (находка, чисто, ошибка).
```

## Правила, без которых тест не примет файл

Образец, который парсер гейта понимает. Первая голая строка `return;`
заканчивает гейт: сравнение сервиса, баннера и порта стоит до неё.

```rhai
// SPDX-License-Identifier: Apache-2.0
// Copyright 2026 onixus
// <что подтверждено и что сознательно не проверялось>
fn name() { "shapo_example" }
fn description() { "One sentence." }
fn ports() { [] }
fn run() {
    let unnamed = service == "" || service == "unknown";
    if !(service == "example" || (unnamed && port == 9)) { return; }
    let reply = probe_send(port, "PING\r\n", 1500);
    if reply.len() == 0 { throw "empty example reply"; }
    if reply.starts_with("-NOAUTH") { return; }
    if !reply.starts_with("+PONG") { throw "unexpected example reply"; }
    return #{
        title: "Example status available without authentication",
        severity: "LOW",
        summary: "The status command returned a complete reply without credentials. This does not prove access to stored data.",
        evidence: "An unauthenticated status command returned a complete reply."
    };
}
```

Что проверяет `tests/test_pulse_plugins_files.py` чтением файла, без запуска Pulse:

- Есть `fn name()`, `fn description()`, `fn ports()`, `fn run()`. `name()`
  возвращает одну строку, равную имени файла без `.rhai`. Имя начинается с
  `shapo_`.
- `ports()` — ровно `[]`. Фильтр порта в `ports()` тест отклоняет.
- Гейт до первого `return;` содержит `service == "имя"` или `svc == "имя"`.
  Сравнение `!=` и `contains` парсер не видит. Таблица
  `pulse_plugins.APPLICABILITY` должна совпасть с тем, что парсер извлёк:
  множество сервисов, пары баннера, множество портов.
- Баннер записывается только как `переменная.starts_with("префикс")` и по
  желанию `&& та_же.contains("фрагмент")`. Одинокий `contains` в таблицу не
  попадает, и верификация потом считает реальный осмотр неприменимым.
- Каждый `port == N` или `number == N` стоит сразу после `unnamed &&`.
  Форма `service == "http" && port == 9200` тесту не подходит. Поэтому
  продукт, который Pulse уже назвал `http`, этим портом не поймать.
- На весь файл не больше четырёх вызовов `probe_send`, `probe_recv`,
  `probe_send_hex`, `probe_udp_hex` и их специализированных обёрток.
  Таймаут — целое число последним аргументом, не переменная. Потолок теста
  5000 мс; в новых файлах писать 1500.
- `http_get` нельзя. HTTP — это одна сырая строка запроса в `probe_send`,
  как в `shapo_http_trace.rhai`. `Host: shapoclyack.invalid` и
  `Connection: close`.
- Исходник только ASCII. Escape байта выше `0x7F` нельзя: песочница отправит
  другие байты. Такой байт уходит через `probe_send_hex`.
- Если в файле есть проба, в нём есть `throw` или `expect(`. Отказ в
  доступе (`401`, `-NOAUTH`, CONNACK с ненулевым кодом) — это `return` без
  карты, не ошибка.
- В первых двенадцати строках `SPDX-License-Identifier: Apache-2.0`.
  Производный от GenDec файл сюда не добавлять: для него отдельные строки в
  `NOTICE` и `docs/third-party.md`, а эти фазы пишутся заново.
- Комментарий не должен притворяться гейтом: парсер вырезает строки с `//`
  и всё равно может увидеть строку в примере. Команды и сравнения сервиса в
  комментариях до первого `return;` не писать.

Карта находки: `title`, `severity`, `summary`, `evidence`. Серьёзность
`critical`, `high`, `medium`, `low` проходит как есть. `info` и любое другое
слово отчёт превращает в `unknown`. Для этих фаз потолок — `LOW`, кроме
случая, где беспарольный ответ уже означает принятое соединение или принятую
команду чтения. `CRITICAL` за открытый порт не ставить.

`summary` одной фразой говорит, что именно не проверялось: данные, запись,
вход, сессия.

Песочница не говорит по TLS. Порт, который обычно TLS (`443`, `636`, `2376`,
`5671`, `5986`, `8883`, `9093`), в безымянный гейт не входит. Если сервис на
нём уже назван пробой по голому ответу, плагин может сработать, но сам
рукопожатие TLS не начинает.

`pulse plugin run` сначала подключается за баннером и только потом выполняет
`probe_send`. Заглушка `Stub` в `tests/test_pulse_plugins_files.py` поэтому
шлёт greeting на первое соединение. Ответ, который должен увидеть плагин,
кладётся в `reply`.

Чужие `.rhai` в этих фазах не менять. Хеши исторических плагинов сверяются с
`tests/fixtures/nmap_pulse_corpus/pulse/plugins.sha256`. Новый файл этот список
не ломает, правка старого — ломает.

Каждый новый файл в том же изменении:

1. Запись в `APPLICABILITY` в `scanner/pipeline/pulse_plugins.py`.
2. Строка в `PLUGIN_ONLY` в `scripts/pulse_corpus.py`: что проверка покрывает
   и чего не утверждает. Иначе `test_every_shipped_plugin_is_accounted_for_against_nse`
   не сойдётся.
3. Три случая в `tests/test_pulse_plugins_files.py` под `@needs_pulse`:
   разобранный ответ даёт находку, отказ в доступе молчит, обрезанный или
   чужой ответ даёт ошибку плагина. Запрос, который ушёл на заглушку,
   проверяется по `server.received`.
4. Строка в таблице плагинов в `docs/pulse-plugins.md`.

Когда фаза целиком переведена в `done`, одна запись в `CHANGELOG.md` в
`Unreleased`. Пока фаза открыта, changelog не трогать.

Проверка одного файла, если на машине есть Pulse:

```text
python3 -m pytest tests/test_pulse_plugins_files.py -q -k '<имя>'
python3 -m pytest tests/test_nmap_pulse_corpus.py::test_every_shipped_plugin_is_accounted_for_against_nse tests/test_pulse_plugins.py -q
```

Без бинарника Pulse поведенческие тесты пропускаются. Контракт файла они не
покрывают: его проверяет первая группа тестов того же файла, она бинарник не
требует.

## Фаза 1 — статус документа, который проба уже умеет спросить

Статус фазы: `done`.

Повтор того же класса, что `shapo_redis_info`: проба узнаёт продукт, плагин
отдельным обменом превращает беспарольный полный ответ в находку. Находка не
равна строке сервиса в `services.json`.

### shapo_clickhouse_ping — `done`

- Сервис: `clickhouse`. Порт без имени: `8123`. Порт `9000` не использовать:
  его делят нативный протокол и другие продукты, а HTTP `/ping` туда слать нечего.
- Запрос: `GET /ping HTTP/1.1` с `Connection: close`.
- Находка `LOW`: статус `200`, тело `Ok.` и заголовок `X-ClickHouse`.
- Чисто: `401`, `403` или код аутентификации ClickHouse в коротком теле ошибки.
- Ошибка: ответ не HTTP, нет конца заголовков, тело обрезано.
- Evidence: полный ответ `/ping` разобран, версия в текст не копируется.
- Не делать: `SELECT`, чтение таблиц, нативный протокол на 9000.
- Тест: `Ok.` с заголовком; `401`; мусор вместо статуса.

### shapo_mongodb_hello — `done`

- Сервис: `mongodb`. Порты без имени: `27017`, `27018`, `27019`, каждый
  отдельным `(unnamed && port == N)`.
- Запрос: один `hello` или `isMaster` на `admin.$cmd` через `probe_send_hex`.
  Байты собрать по описанию команды, не копировать строку из `probes.json`.
- Находка `LOW`: документ разобран и содержит признак ответа (`ismaster` или
  `maxBsonObjectSize`) без требования входа.
- Чисто: ответ об ошибке авторизации, который ещё укладывается в документ.
- Ошибка: длина документа не сходится, документ обрезан, ответ не BSON.
- Evidence: команда hello ответила без входа. Список баз и значения полей не
  сохранять.
- Не делать: `listDatabases`, `find`, учётку.
- Тест: маленький документ с `ismaster`; документ-ошибка авторизации; оборванная длина.

### shapo_etcd_version — `done`

- Сервис: `etcd`. Порт без имени: `2379`. Порт `2380` не добавлять.
- Запрос: `GET /version`.
- Находка `LOW`: `200` и JSON, в котором есть `etcdserver` или `etcdcluster`.
- Чисто: `401` или `403`.
- Ошибка: не HTTP, JSON обрезан так, что поле версии не закрыто, статус без тела там,
  где длина обещана.
- Evidence: беспарольный `/version` разобран. Номер версии в текст можно не класть.
- Не делать: `/v2/keys`, диапазоны, запись.
- Тест: короткий JSON версии; `401`; статус без заголовков.

### shapo_docker_version — `done`

- Сервис: `docker`. Порт без имени: `2375`. Порт `2376` не добавлять: там TLS.
- Запрос: `GET /version`.
- Находка `LOW`: `200` и JSON с `ApiVersion` либо с компонентом `Engine`.
- Чисто: `401` или `403`.
- Ошибка: не HTTP или JSON без закрытия там, где ответ оборван.
- Evidence: API движка ответило на `/version` без входа. Хост, контейнеры и
  право монтировать файловую систему отсюда не следуют и в тексте не упоминаются
  как установленный факт.
- Не делать: `/containers/create`, `/images/create`, сокет, чтение контейнеров.
- Тест: JSON с `ApiVersion`; `401`; обрыв на первой строке статуса.

## Фаза 2 — панели, у которых проба уже ставит своё имя сервиса

Статус фазы: `done`.

Имена взяты из совпадений `http-get-api`. Плагин не матчится на `service == "http"`:
иначе запрос уйдёт на каждый веб-порт. `elasticsearch`, `opensearch` и `minio`
проба уже называет своими именами; плагины для них не писать, пока их не попросят.
Если на стенде сервис остался `http`, пункт не «чинится» расширением гейта.
Это повод дать продукту своё имя в пробе, отдельным изменением, и только потом
сменить статус пункта.

### shapo_prometheus_ready — `done`

- Сервис: `prometheus`. Порт без имени: `9090`.
- Запрос: один `GET /api/v1/status/buildinfo`. Путь `/-/healthy` не использовать:
  слово `Healthy` встречается у чужих проверок, а второго запроса в файле нет.
- Находка `LOW`: `200` и JSON с `"status":"success"`.
- Чисто: `401` или `403`.
- Ошибка: не HTTP, оборванный JSON или `200` без этого поля.
- Evidence: buildinfo ответил без входа. Метрики и значения label не сохранять.
- Не делать: `GET /metrics`, запросы PromQL.
- Тест: короткий `{"status":"success"}`; `401`; слово `Healthy` без JSON
  (это ошибка разбора, не находка).

### shapo_grafana_health — `done`

- Сервис: `grafana`. Порт без имени: `3000`.
- Запрос: `GET /api/health`.
- Находка `LOW`: `200` и JSON, где поле database или commit выдаёт Grafana,
  а не произвольное слово `ok` в чужом продукте.
- Чисто: `401` или `403` на этом пути.
- Ошибка: не HTTP, обрезанный JSON.
- Evidence: health ответил без входа. Список дашбордов не запрашивать:
  `/api/search` в этот пункт не входит.
- Не делать: вход, `/api/admin`, дамп дашборда.
- Тест: health с признаком Grafana; `401`; `200` с телом `ok` без полей Grafana
  (ошибка разбора).

### shapo_jenkins_anonymous — `done`

- Сервис: `jenkins`. Порты без имени: `8080` и `8088`.
- Запрос: `GET /whoAmI/api/json`. Если этот путь для установленного Jenkins
  другой, дописать сюда точный путь до начала кода, не угадывать в плагине два URL.
- Находка `LOW`: `200` и JSON анонимного пользователя либо заголовок
  `X-Jenkins` на ответе `200` этого же URL. Заголовок на `403` находкой не
  является: это уже узнавание продукта пробой.
- Чисто: `401` или `403`.
- Ошибка: не HTTP.
- Evidence: анонимный whoAmI разобран. Имя пользователя, если оно не
  `anonymous`, в evidence не копировать.
- Не делать: console script, вход, запуск задачи.
- Тест: JSON анонимного пользователя с `X-Jenkins`; `403` с тем же заголовком
  (молча); обрыв.

### shapo_consul_status — `done`

- Сервис: `consul`. Порт без имени: `8500`.
- Запрос: `GET /v1/status/leader`.
- Находка `LOW`: `200` и тело в кавычках JSON-строки (адрес лидера). Содержимое
  адреса в evidence не класть.
- Чисто: `401` или `403`.
- Ошибка: не HTTP, тело не является одной JSON-строкой и не является пустым
  ответом отказа.
- Evidence: leader status ответил без входа.
- Не делать: `/v1/kv`, каталог, токены ACL.
- Тест: `"127.0.0.1:8300"`; `403`; HTML.

### shapo_vault_health — `done`

- Сервис: `vault`. Порт без имени: `8200`.
  Проба `http-get-api` этот порт сейчас не опрашивает, поэтому безымянный
  порт здесь нужен. Не расширять список портов пробы в том же изменении, что
  и плагин.
- Запрос: `GET /v1/sys/health`.
- Находка `LOW`: JSON с полем `initialized` или `sealed`, статус при этом любой,
  кроме `401` и `403`. Этот путь отвечает о состоянии хранилища разными
  кодами, поэтому код сам по себе продукт не доказывает и не опровергает.
- Чисто: `401` или `403`.
- Ошибка: не HTTP, обрезанный JSON или статус вне `401`/`403` без этих полей.
- Evidence: health разобран. Поля `cluster_name` и номера версий не копировать.
- Не делать: перебор токенов, `/v1/secret`, init и unseal.
- Тест: `200` с `sealed`; `503` без JSON Vault (ошибка); `403`.

### shapo_kube_version — `done`

- Сервис: `k8s-api`. Безымянного порта нет: `6443` обычно TLS, песочница TLS не говорит.
- Запрос: `GET /version`.
- Находка `LOW`: `200` и JSON с `major` и `gitVersion`.
- Чисто: `401` или `403`.
- Ошибка: не HTTP или JSON без этих полей при статусе `200`.
- Evidence: `/version` ответил без входа. Список объектов API не запрашивать.
- Не делать: `/api/v1/pods`, exec, kubelet.
- Тест: короткий version JSON; `401`; `200` с пустым объектом (ошибка).

## Фаза 3 — один обмен с брокером или каталогом

### shapo_kafka_apiversions — `done`

- Сервис: `kafka`. Порт без имени: `9092`. `9093` и `9094` не добавлять.

## Фаза 7 — волна для написания

Статус фазы: `done`. Это следующая пачка для реализации. Пункты ниже уже
с критерием: путь один, второй не подбирать. Закрытые фазы 0–4 не править.

Серьёзность всех пунктов — `LOW`. В evidence статичная фраза о факте разбора.
Туда не класть тело, версию, uuid, адрес, имя пользователя, список и дамп.
`summary` одной фразой говорит, что список, запись и вход не проверялись.

Общее для HTTP-пунктов:

- Одна строка в `probe_send`, таймаут `1500`. Образец запроса —
  `shapo_clickhouse_ping.rhai`: `GET <path> HTTP/1.1`, `Host: shapoclyack.invalid`,

- `trim()` и `replace()` меняют строку на месте и возвращают `()`. Писать их

библиотеки, подбор, вердикт «пропатчено» и свободный текст. Плагин Pulse —
один обмен на уже открытом порту, гейт по `service` пробы, отказ в доступе
молчит, обрезанный ответ — ошибка, evidence без тела. Поэтому большинство
скриптов NSE в этот контракт не встаёт.

## Не писать

Пункты ниже не ждут критерия. Новый похожий запрос сначала сравнивается с
этим списком и с фазой 9.

| Тема | Почему не плагин |
|---|---|
| MySQL и PostgreSQL по приветствию | Проба уже пишет продукт. Беспарольный доступ без попытки входа не виден, а попытка входа в эти фазы не входит. |
| Elasticsearch, OpenSearch, MinIO на каждом HTTP | Фаза 8 закрыла гейт по имени сервиса пробы. Гейт на `service == "http"` или на все HTTP-порты по-прежнему не принимается. Списки индексов и бакетов остаются в фазе 9 как `blocked`. |
| Приветствие HTTP и версия в `Server` | Это результат пробы, не отдельная находка. |
| Версия TLS из текста баннера | Версии смотрит рукопожатие в `tls_posture.py`. |
| SMTP-реле, VRFY, EXPN | STARTTLS уже смотрит `shapo_cleartext_services`. Реле — это отправка почты, VRFY — перечисление пользователей. |
| HTTPS TRACE, заголовки по HTTPS, GraphQL на каждом сайте | У плагина нет TLS. POST introspection на каждый `http` в очередь не ставить, пока нет сервиса `graphql`. |
| vLLM и прочие LLM на `8000`/`8080` | Порт общий. Пункт появится, когда проба поставит отдельное имя сервиса. Ollama остаётся в фазе 4 из-за порта `11434`. |
| Spark UI и Hadoop NameNode | Своего `service` нет, порты пересекаются с обычным HTTP. |
| Печать MS10-061, полный набор шифров RDP, сессия VNC, каталог FTP через PASV, подбор SNMP community, подтверждение эксплуатации MS17-010 | Либо нужен второй порт или чужой кадр, либо проверка утверждала бы больше, чем позволяет один безопасный обмен. |
| Копии `db_exposure_audit` и остальных port-open скриптов GenDec | Находка на открытый порт. Фаза 0 уже покрывает те же службы точнее. |
