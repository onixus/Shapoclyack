> longer moved. See [Migrating off Nmap](../nmap-migration.md).

## Changes since 0.46

Everything in the [0.47-1009-rc1 notes](0.47-1009-rc1.md#changes-since-046),
plus:

- Scanner: Pulse `v1.4.0` with Rhai protocol plugins, raw TLS suite enumeration
  and `tls_posture` grading; L2 discovery through Pulse; NSE `vuln` coverage
  through Nuclei network templates and Rhai. Naabu stays the port backend
  ([ADR-0003](../adr/0003-port-discovery-backend.md)).
- Findings: production evidence and its replay keep lifecycle, identity and
  assessment; opt-in directed Nuclei planning with explicit skip receipts;
  reviewed non-CVE findings in the shared workflow.
- Fleet trust: per-sensor Ed25519 result signatures, result schema checks
  (default `warn`) and opt-in sensor health/metrics.
- Integrations: API v1 aliases, cursor exports and a generated client;
  configurable ticket mapping with GitHub/GitLab transports; CSV/XLSX reports,
  signed manifests and S3 delivery; ServiceNow CMDB connector; service-token
  overlap rotation and source CIDRs.
- Deployment: a Helm chart rendered from the Kustomize base with parity checks.
- Console: personal saved views and keyboard accessibility. Browser screenshot
  capture is withdrawn; historical artifacts stay readable.
- Image security: upstream OpenSSH 10.6p1 client (CVE-2026-60002), Go 1.26.10
  tool rebuilds, current `aiohttp`, `certifi` and Pillow pins, complete Ubuntu
  USN refresh and an optional NVD key as an ephemeral BuildKit secret.

The complete change list is in [CHANGELOG.md](../../CHANGELOG.md). Lariska is
released separately; these notes describe the platform's protocol support and
do not claim that every installed endpoint Agent implements it.

## Before upgrading

1. Back up PostgreSQL and the applicable artifact/ClickHouse stores and confirm
   a restore path before migrating. Follow
   [Upgrade and rollback](../operations.md#upgrade-and-rollback), including its
   migration-specific downgrade losses. An image rollback is not permission to
   run a blanket database downgrade.
2. Coming from 0.46, complete the rc1 upgrade steps first:
   [idempotency migration `0082`](0.47-1009-rc1.md#before-upgrading-a-validation-environment),
   tenant MFA enrolment, and signed native replacements for stored unsigned
   endpoint builds.
3. Remove Nmap from scan configs: the Nmap backend and `nmap_timing` are
   refused. Old runs stay readable. See [Migrating off Nmap](../nmap-migration.md).
4. The `scanner-executor` StatefulSet gains a `sensor-key` volume claim
   template. Delete it with `--cascade=orphan` and apply again; on a cluster
   without a default StorageClass, set `storageClassName`. See
   [sensor result integrity](../operations.md#sensor-result-integrity-schemas-and-signatures).
   Enforce result signatures fleet-wide only after every sensor runs `0.48-1021`.
5. Deploy all components explicitly by their verified `tag@sha256:digest`, then
   update the repository's deployment defaults and installer pins to the
   published digests in a follow-up change.

## Publication checklist

- [ ] Merge the release-preparation PR through the protected `main` workflow.
      Record the exact resulting commit and confirm the API/sensor version,
      changelog and database head from that commit.
- [ ] Complete the repository Jenkins CI on that revision, including the
      main-only Load stage that feature branches skip.
- [ ] Confirm the git tag and the three GHCR tags (scanner, api, aio) are
      unused: registry checks must return `MANIFEST_UNKNOWN`. Network or
      authentication failures do not prove that a tag is free.
- [ ] Create an annotated `shapoclyack-0.48-1021` tag on the verified commit and
      make it available to the Jenkins job's source clone. Pushing a tag or
      creating a GitHub Release does not build images.
- [ ] Run `shapoclyack-publish` with `TAG=shapoclyack-0.48-1021`,
      `DRY_RUN=true`, `MULTIARCH=true`, `ONLY` empty. Require all three builds,
      the *Pulse is latest* stage and the signing-key check to pass.
- [ ] Publish with the same tag and `DRY_RUN=false`. Record the three
      image-index digests and verify `linux/amd64` and `linux/arm64`. As a
      stable release this moves `latest`.
- [ ] Verify image signatures and SLSA provenance using
      [Supply chain](../supply-chain.md#verify-an-image), and Pulse in scanner
      and aio on both platforms using
      [Release contract](../release-contract.md#what-a-customer-can-verify-and-how).
- [ ] The stable publish job signs the sensor bundle with the release key.
      Verify it against `cosign.pub` before placing it in `OCTO_AGENT_BUNDLE_DIR`.
- [ ] Test readiness, sign-in/MFA, a local and a sensor scan through result
      publication, inventory ingestion, native update negotiation and mechanical
      re-verification. `GET /api/system` must report `0.48-1021`; current
      sensors must not appear outdated.
- [ ] Create the GitHub Release (not a prerelease) with the verified digests,
      CI evidence and these notes. Then update
      [SECURITY.md](../../.github/SECURITY.md#supported-versions) to make `0.48`
      the supported line, and move the deployment digest pins.
