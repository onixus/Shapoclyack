# Корпоративная база знаний (Wiki) Shapoclyack

Добро пожаловать в корпоративную базу знаний платформы **[Shapoclyack](https://github.com/onixus/Shapoclyack)** — self-hosted решения классов **EASM** (External Attack Surface Management), **CAASM** (Cyber Asset Attack Surface Management) и **RBVM** (Risk-Based Vulnerability Management).

База знаний актуализирована в соответствии с пререлизом **[`shapoclyack-0.49-1111-rc1`](https://github.com/onixus/Shapoclyack/releases/tag/shapoclyack-0.49-1111-rc1)** от 11 ноября 2026 года (`main @ f01c2b6a`, после PR #644; миграции БД `0097`–`0106`, голова схемы `0106_saml_session_binding`, нативный движок **Pulse `v1.5.0`**) и объединяет ролевые сценарии эксплуатации, регламенты процессов ИБ и сквозное сопоставление возможностей платформы со стандартами **NIST** и **нормативно-правовыми актами РФ (ФСТЭК России, 187-ФЗ, ГОСТ, Банк России)**.

## 💎 Ключевые архитектурные принципы Shapoclyack

1. **Устойчивая идентичность актива вместо временного IP-адреса:** история уязвимостей, бизнес-владелец, категория значимости КИИ и принятые риски привязаны к подтверждённому активу ([`docs/asset-identity.md`](../asset-identity.md)), а не теряются при смене DHCP-аренды или пересоздании контейнера.
2. **Механически подтверждённое устранение (`Closed-Loop Remediation`):** закрытие тикета в Jira или ServiceNow не переводит уязвимость в статус верифицированной. Платформа требует повторного прогона всех обнаруживших проблему детекторов (`machine_verified = true`); если порт просто закрыт межсетевым экраном с точки наблюдения сенсора, фиксируется `endpoint_unreachable` при `machine_verified = false` ([`docs/vulnerability-lifecycle.md`](../vulnerability-lifecycle.md)).
3. **Безопасность сканирования по умолчанию (`Fail-Closed Scope` и отказ от Nmap):** сканирование запускается только в пределах явно утверждённой администратором области (`approved scope`). Вместо монолитного Nmap используется детерминированный движок **Pulse `v1.5.0`** с вынесенными в версионируемый контур read-only плагинами Rhai (`scripts/fetch-pulse-plugins.sh` → `service_probe.pulse.plugins_dir`), что исключает неконтролируемое выполнение сторонних NSE-скриптов в сегментах КИИ и АСУ ТП ([`docs/nmap-migration.md`](../nmap-migration.md)).
4. **Разделение ролей Сенсора и Агента:** **Сенсор** (`agent_kind = scanner`) забирает задания сканирования по исходящему соединению NATS JetStream (с mTLS) или HTTPS, а хостовый **Агент Lariska** (`agent_kind = endpoint`) только передаёт подписанные слепки инвентаризации (`POST /api/endpoint/inventory`) для точного расчёта `Patch Gaps` с учётом бэкпортов дистрибутивов ([`docs/endpoint-inventory-v2.md`](../endpoint-inventory-v2.md)).
