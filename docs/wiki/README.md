## 💎 Ключевые архитектурные принципы Shapoclyack

| Принцип | Практическое значение | Технический контракт |
|---|---|---|
| Актив первичнее IP | История связана с подтверждённой идентичностью; смена адреса сама по себе не доказывает связь активов | [Идентичность активов](../asset-identity.md) |
| Вероятность и ущерб — отдельные оси | Зрелость эксплойта ограничивает вероятность, бизнес-критичность определяет ущерб | [Модель риска](../risk-scoring.md) |
| Закрытие требует доказательств | Машинная проверка должна повторить детекторы; недоступность порта и ручное закрытие не считаются подтверждённым устранением | [Жизненный цикл и SLA](../vulnerability-lifecycle.md) |
| Пакеты оцениваются по бюллетеням дистрибутива | Бэкпорты учитываются; отсутствие данных не означает отсутствие уязвимости | [Сопоставление ПО и CVE](../software-cve-matching.md) |
| Результат измеряется | Подтверждённые закрытия, MTTR, SLA и шум отражаются в метриках | [Web UI](../ui.md) |

**Сенсор** запускает сканы (`agent_kind = scanner`); **агент** Lariska собирает
инвентаризацию внутри хоста (`agent_kind = endpoint`). Имена пакета `agent/`,
API-ресурса `agents` и переменных `OCTO_AGENT_*` сохранены в коде.
